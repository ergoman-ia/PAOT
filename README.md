# v3 공유 적립 구조 — 배포 안내

## 1. 질문에 대한 답

**기존 구조는 서버에 아무것도 남지 않습니다.** 접속자가 생성한 자료는 그 사람 브라우저(localStorage)에만 저장되어, 시크릿창을 닫거나 다른 PC로 옮기면 사라지고 다른 사람은 존재조차 모릅니다. 서버의 `default_cache.json`은 읽기 전용 정적 파일이라 앱이 여기에 쓸 방법이 없었습니다. 즉 **A교육생이 3분 걸려 만든 "조선업/도장공"을 B교육생이 또 3분 걸려 만드는** 상태였습니다.

말씀하신 방향이 맞습니다. v3에서 그렇게 바꿨습니다.

## 2. 바뀐 구조

```
      ┌── 접속자 ─────────────────────────────────────────────┐
      │ 업종·직종 입력                                          │
      │      │                                                 │
      │      ├─ 공용 목록에 있음 → 그 직종 1건만 내려받아 즉시 완료 │
      │      │                     (0.05초 · AI 호출 0회 · 무료)  │
      │      │                                                 │
      │      └─ 없음 → 화면에서 생성 (20~40초)                    │
      │              + 등록용 파일 cp-xxxxxxxx.json 자동 저장     │
      │              + [교수실에 등록 요청] 메일 버튼 표시          │
      └────────────────────────┬────────────────────────────────┘
                               │ 메일 첨부
      ┌── 교수실 (admin.html) ─▼──────────────────────────────┐
      │ 파일 끌어다 놓기 → 무결성 자동 검사 → [GitHub에 반영하기]  │
      │ 1~2분 뒤 GitHub Pages 재배포 → 그 시점부터 전원 즉시 사용  │
      └───────────────────────────────────────────────────────┘
```

### 핵심 변경 1 — 캐시를 조각내고 목록만 먼저 준다

기존처럼 캐시를 한 덩어리로 두면 **직종이 늘수록 모든 접속자가 느려집니다.** 직종 1건이 약 80KB이므로 500직종이면 40MB를 매번 내려받게 됩니다. 그래서 목록과 본문을 분리했습니다.

| | 기존 (단일 파일) | v3 (카탈로그 + 조각) |
|---|---|---|
| 부팅 시 전송량 | 1.61 MB (20직종) | **2.4 KB** (목록만) |
| 500직종으로 늘면 | 약 40 MB | 약 60 KB |
| 필요한 직종 1건 | (이미 다 받음) | 80 KB, 1회만 (이후 브라우저 캐시) |

### 핵심 변경 2 — 표기가 달라도 찾아준다

"건설 / 철근"만 입력해도 공용 목록의 "건설업 / 철근공"을 찾아 버튼으로 제시합니다. 공백·괄호·가운뎃점·대소문자는 무시하고 대조하므로 같은 직종이 표기 차이 때문에 중복 생성되는 낭비를 막습니다.

### 핵심 변경 3 — 교수실 반영이 버튼 한 번

`admin.html`에서 접수 파일을 끌어다 놓으면 **132문항 존재 여부, 선별 ID가 전부 실재하는지, 문장 손상 여부**를 자동 검사해 통과한 것만 반영 목록에 올립니다. 이후 [GitHub에 반영하기] 한 번이면 커밋·재배포까지 끝납니다.

## 3. 파일 구성

```
저장소/
├─ index.html          ← index_v2.html 을 이 이름으로 (접속자용)
├─ admin.html          ← 교수실 전용. 접속자에게 링크를 안내하지 마세요
└─ data/
   ├─ catalog.json     ← 목록 (2.4KB). 접속자가 부팅 때 받는 유일한 데이터
   ├─ cp-85615788.json ← 항공산업/지상조업사
   └─ … (20개)
```

파일명은 업종·직종을 해시한 **ASCII 고정 이름**입니다. 한글 파일명은 브라우저·운영체제·저장소마다 인코딩이 달라 다운로드나 업로드 과정에서 깨지므로 쓰지 않았습니다. 사람이 읽을 이름은 `catalog.json`이 들고 있어 화면에는 항상 한글로 나옵니다.

## 4. 배포 절차

1. GitHub 저장소에 위 구조 그대로 올립니다. (기존 `default_cache.json`은 지워도 되고, 남겨두면 `catalog.json`이 없을 때만 예비로 쓰입니다.)
2. Settings → Pages → 배포 브랜치 지정.
3. `index.html` 안의 `__GEMINI_API_KEY__`를 실제 키로 치환. **치환하지 않아도 공용 조회·선별·보고서·인쇄는 전부 동작하며 신규 재작성만 꺼집니다.**
4. `index.html` 맨 위 `CONFIG`에서 연락처를 확인하세요.

```js
const CONFIG = {
  DATA_DIR: 'data',
  CONTACT: 'koshaedu@kosha.or.kr',   // 등록 요청 메일 수신 주소
  ORG: '산업안전보건교육원 교수실'
};
```

## 5. 교수실 운영 (직종 1건 등록에 약 1분)

1. 교육생이 [등록 요청] 버튼을 누르면 메일이 작성됩니다. 안내대로 `cp-xxxxxxxx.json`을 첨부해 보냅니다.
2. `admin.html`을 열고 받은 파일을 2번 영역에 끌어다 놓습니다. 여러 개를 한 번에 올려도 됩니다.
3. [GitHub에 반영하기]를 누릅니다.

**토큰 발급 (최초 1회):** GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Repository access에서 이 저장소 하나만 선택 → Permissions에서 **Contents: Read and write** 하나만 부여. 토큰은 교수실 담당자 브라우저에만 저장되며 배포되는 파일에는 들어가지 않습니다.

토큰 발급이 부담되면 **B안**을 쓰시면 됩니다. [변경 파일 내려받기]로 받은 파일을 GitHub의 `data/` 폴더에서 Add file → Upload files로 올리고 Commit하면 동일한 결과입니다.

4번 영역에서는 품질에 문제가 있는 직종을 공용 목록에서 제외할 수 있습니다.

## 6. 왜 "즉시 자동 등록"이 아닌지

GitHub Pages는 정적 호스팅이라 쓰기를 받아줄 서버가 없습니다. 접속자 브라우저에서 저장소에 직접 쓰게 하려면 쓰기 권한 토큰을 HTML에 심어야 하는데, 그러면 **누구나 저장소 전체를 고칠 수 있게 되어** 공공기관 배포에는 쓸 수 없습니다.

그래서 v3은 **읽기는 완전 자동·즉시, 쓰기는 교수실 승인 한 번**으로 나눴습니다. 교육생이 겪는 체감은 이렇습니다.

- 이미 등록된 직종 → 0.05초, 무료
- 새 직종 → 20~40초 (기존 4~9분)에 본인 것은 바로 사용, 등록은 나중에 반영

부수 효과로 **교육자료 품질 통제권이 교수실에 남습니다.** AI가 만든 문장이 검토 없이 공용 교육자료가 되는 일은 없습니다.

완전 자동 등록이 꼭 필요하시면 서버 조각이 하나 필요합니다. 무료 범위에서 가능한 선택지는 Google Apps Script(구글 계정만으로 10분), Cloudflare Workers+KV(가장 빠름) 정도이며, 어느 쪽이든 **Gemini 키를 서버로 옮겨 현재의 키 노출 문제까지 함께 해결**됩니다. 말씀 주시면 그 구조로 바꿔 드리겠습니다.

## 7. 검증

Chromium 자동 테스트로 전 과정을 통과했습니다 (핵심 기능 19건 + 공유 흐름 21건).

접속자A 공용 적중 0.05초·AI 0회 → 표기 흔들림("건설/철근") 추천 → 접속자B 미등록 생성(범주 9개 동시, 132문항) → 등록용 파일 무결성(132/54/20) → 교수실 접수·검증·손상파일 거부 → 반영 → **접속자C가 같은 직종을 AI 0회·0.04초로 사용, 내용은 B의 생성본과 완전 동일.**
